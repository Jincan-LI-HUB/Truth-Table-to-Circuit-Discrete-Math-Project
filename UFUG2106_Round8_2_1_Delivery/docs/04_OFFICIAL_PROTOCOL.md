## Required release gates

1. **Direct resource:** all test cases generated with positive RAM 9,000 KiB have child peak RSS not exceeding 9,000 KiB and pass the independent exhaustive verifier.
2. **Official resource:** the real evaluator reports `PASS` and `target_met=yes` for at least the 20-input wire, XOR, multi-output and full-support AND tests under RAM 9,000 KiB. These cases are generated by a generic script and are not hardcoded in the solver.
3. **Official released banks:** in each run, all variants tested must return 25/25 PASS and 25/25 Target Met on **both stages**. The official CSV files and logs are preserved verbatim.
4. **Comparability:** same policies in R8.2 and R8.2.1 (`fast_adp`, `fast_area`, `dual_area`). Compare area, delay and per-case runtime; investigate substantial drift rather than declaring the patched binary automatically faster or better.
5. **Feedback integrity:** on either success or failure the script emits a single feedback ZIP with source hashes, resource direct and official records, official CSV, benchmark logs, and research documents. A nonzero gate stops the official pipeline and returns a nonzero exit code.

An official PASS at RAM 9,000 KiB only certifies the tested inputs. **It is not a proof of universal resource safety under all possible cases.**
