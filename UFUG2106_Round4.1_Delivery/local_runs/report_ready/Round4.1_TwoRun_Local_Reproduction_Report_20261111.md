# UFUG2106 — Round 4.1 双次本地复现实验报告

**实验日期：** 2026-11-11  |  **实验阶段：** Round 4.1 — Runtime Optimization  |  **数据来源：** 用户 WSL2 本地两次完整实验结果包

> **结论。** Strict、Balanced、Fast 三种配置在两次独立执行中均为 **25/25 PASS、25/25 Target Delay Met**。共 150 次官方案例测评全部成功。两次运行产生的同一配置 Netlist **逐字节相同**；只存在运行时间的测量波动。

## 1. 研究目标与实验定义

上一阶段 Round 4 已在 25 个公开 Stage 1 案例上达到 Area 总和 528,910，全部电路正确且满足目标延迟，但重复综合多份 BDD 候选及反复进行全图极性优化造成额外 Runtime。Round 4.1 不改变逻辑功能或合法 Gate 集，而是优化综合器执行中的重复计算与搜索预算。

令 \(C\) 表示输出的合法门级电路，目标是：

\[\min A(C),\qquad D(C)\le D_{\mathrm{target}},\qquad T_{\mathrm{alg}}\le T_{\mathrm{limit}},\qquad C\equiv f.\]

这里 \(A(C)\) 为各门面积之和，\(D(C)\) 为关键路径延迟，\(T_{\mathrm{alg}}\) 为综合程序运行时间。**正确性与测评 Target Delay 是两类不同的条件；Target Delay 不达标并不自动等于逻辑不正确。** Round 4.1 本次两者全部达成。Area 总和是跨案例描述性指标，并非教师未公布的最终评分。

### 1.1 三种版本的设计差异

- **Strict**：缓存输入真值表和变量影响度，减少极性搜索冗余，但保留足够候选，使本次公开 25 案例与 Round 4 的结果相同。
- **Balanced**：进一步压缩极性搜索候选数量，降低 Runtime，可能错失少量面积优化机会。
- **Fast**：在缓存及极性搜索削减之外进一步裁剪 BDD / 综合候选，优先降低 Runtime，允许更多 Area 损失。

以上不是三个不同的正确性标准；三种策略均通过相同的合法性与等价性验证。差异在于搜索预算与候选集。

## 2. 数学与算法依据

### 2.1 Truth Table / Influence 缓存

对第 \(i\) 个输入变量 \(x_i\)，设 \(f_j\) 为第 \(j\) 个输出。变量影响度可以定义为：

\[ I_i=\sum_{x: x_i=0}\sum_{j=0}^{m-1}\mathbf{1}\!\left[f_j(x)\ne f_j(x\oplus e_i)\right]. \]

其中 \(e_i\) 表示仅翻转变量 \(x_i\) 的二进制掩码。影响度由 Truth Table 唯一决定，与后续某个门级映射候选的参数无关，因此可以在一轮综合过程中计算一次、作为只读数据共享。

如果有 \(k\) 组综合候选，重复计算影响度需要 \(O(k n m 2^n)\) 次布尔比较；缓存后该部分降至 \(O(n m 2^n)\)，加上候选读取缓存的额外开销。此复杂度只描述影响度计算，**不意味着整个 BDD 综合算法降为线性时间**。存储解码后的 Truth Table 需要 \(O(m2^n)\) 空间。

### 2.2 搜索空间缩减不影响布尔等价性

Shannon 展开及后续 De Morgan、吸收律、分配律重写属于恒等变换。以 Shannon 恒等式为例：

\[ f=\neg x_i\land f_{x_i=0}\;\lor\;x_i\land f_{x_i=1}.\]

由 \(x_i=0\) 与 \(x_i=1\) 分别代入即可验证等价。搜索时舍弃部分候选，**不会破坏已保留候选的功能正确性**，只可能降低所能找到的面积/延迟最优程度。最终电路的有效性仍需独立验证，不能从启发式选择本身推出。

### 2.3 三维权衡和实验意义

优化问题实际上同时涉及 \(A(C)\)、\(D(C)\) 与 \(T_{\mathrm{alg}}\)。当全部候选满足 Timing Target 时，减少更多搜索步骤可以大幅降低综合用时；但这一收益未必以同样比例反映在 Area。Strict、Balanced、Fast 代表这一 Area–Runtime Trade-off 的三组经验设计点，而**不是全局 Pareto 最优的数学证明**。

## 7. 两次测量稳定性、解释边界与结论

相比 Run 1，Run 2 的中位 Runtime 并非对每个版本都单调变小：Strict 为 111.149→117.527 ms；Balanced 为 96.048→102.615 ms；Fast 为 67.605→63.035 ms。由于每次运行的顺序固定为 Strict→Balanced→Fast，且两次之间没有随机化版本顺序，可能存在缓存/系统负载/温度的顺序效应。**仅有两次测量不足以建立严谨置信区间或硬件无关的加速保证。**

### 7.1 推荐冻结方案

**建议将 Balanced 作为 Round 4.1 默认研究候选，Strict 保留为面积对照，Fast 保留为运行时间对照。** 理由是 Balanced 的总 Area 只比 Strict 增加 104（约 0.020%），但两次运行的中位时间分别降至 96.048 与 102.615 ms；Fast 在本地中位时间更低，但 `case_018` 等局部 Area 退化需要明确记录。

若最终评分对 Area 赋予极高权重，Strict 仍有价值；若 Runtime 限制更紧，Fast 可能更有优势。由于教师尚未公布完整评分函数，不能直接证明任一档具有最高分。

### 7.2 下一轮研究方向

1. **BDD 构造缓存：** 对相同 Variable Order 的不同 Gate Mapping 候选复用 BDD，减少 \(k\) 次结构重复构建。这是更强的公共子问题消除，不只是缓存 Truth Table。
2. **增量成本评估：** 对局部极性变更和 DAG 重写维护受影响 Gate 的 Area / Arrival Time，减少每次全图重算。
3. **条件式搜索预算：** 根据 BDD 节点数、已找到候选的 Area、Timing Slack 和边际收益调整候选数量，而非固定每次遍历相同集合。
4. **更严格的中断机制：** 对单个候选的构造、后处理均增加超时及节点数量检查，以避免在未知高熵函数上超时。
5. **更科学的性能基准：** 建议在 WSL 原生文件系统再跑一组，随机化三种配置运行顺序并增加重复次数，区分真实算法收益与 I/O/负载影响。
