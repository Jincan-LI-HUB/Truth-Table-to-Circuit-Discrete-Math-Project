## 1. One-command reproducibility

Start from WSL inside the Project Root:

```bash
BASE="/mnt/e/canfiles/Common courses study/大学通识/26-27 Fall/UFUG 2106 Discrete Math/assignment/Final Project"
cd "$BASE" || exit 1
bash UFUG2106_Round7_1_Delivery/run_round71.sh
```

By default this performs:

1. Derive standalone R7.1 source from exact frozen R5.1 + audited R7 Cover patch + R7.1 scheduler patch; compile `-O2 -std=c++17 -pipe -DNDEBUG`.
2. Verify all ten scheduler patch anchors and compile/compare R7 exact cover kernels on 10,656 independent combinations.
3. Run **two complete paired repetitions** on both official Stage 1 and Stage 2 datasets. At each repetition, execute the frozen R5.1, R7.1 guarded default, R7.1 scheduler-off ablation, and two one-kernel ablations; reverse variant ordering for repetition 2.
4. Run `case_016` diagnostics with candidate-level trace and independent exhaustive truth-table verification (not under official 100 ms limit).
5. Generate all full CSVs, evaluator logs, `casewise_comparison.csv`, `EXPERIMENT_REPORT.md`, `summary.json`, and pack everything into a feedback ZIP.

**Important:** The final feedback ZIP is produced even if compilation, unit testing, the evaluator, or the public release gate fails. The shell exits nonzero when the release gate fails. Upload the ZIP as-is.

An illustrative terminal ending:

```text
RELEASE_GATE: PASS/FAIL
FEEDBACK ZIP CREATED: .../feedback/Round7.1_Feedback_<timestamp>.zip
Upload this single ZIP for the next analysis.
```

This text is a format example, not a prediction of PASS.

## 3. Experimental modes and attribution

Environment variables for a **single** executable invocation:

| Setting | Meaning | Used by benchmark driver |
|---|---|---|
| `UFUG_R71_POLICY=guard` (or absent) | Guard short-budget dispatch | Default experimental treatment |
| `UFUG_R71_POLICY=off` | Preserve Round 7 candidate-dispatch policy (small timing-origin difference) | Scheduler ablation |
| `UFUG_R7_LEGACY_MERGE=1` | Old quadratic merge, fast bitset greedy | Kernel ablation |
| `UFUG_R7_LEGACY_COVER=1` | Fast hash-neighbor merge, old greedy | Kernel ablation |
| `UFUG_R71_TRACE=1` | Emit per-candidate trace on stderr | Diagnostics only |
| `UFUG_ROUND5_PROFILE=1` | Emit R5/R7 stage timings | Diagnostics only |

The official driver **strips all five variables** and passes the intended configuration to every invocation. This prevents accidental environment contamination. The official evaluator's `--report` writes CSV files; logs are stored separately. It copies the evaluator into a native Linux temporary directory to avoid Windows-mounted drive execution permissions, without modifying its contents.

## 4. What must be judged before accepting Round 7.1?

### First, feasibility

- All 25 Stage 1 and 25 Stage 2 cases officially PASS in *both* repetitions.
- All 50 successful cases meet their target delays. (The target is a quality criterion, not a general statement about official PASS.)
- No new Stage 1 errors or memory breaches.
- For short-limit cases, repeated runtime is **not borderline**. Compare the maximum observed utilization \(u_i=T_i/L_i\), not just medians.

### Next, quality

For each case passing in **both** methods, compute:

\[
r_i^A=\frac{A_i^{\mathrm{R7.1}}}{A_i^{\mathrm{R5.1}}},\quad
\Delta D_i=D_i^{\mathrm{R7.1}}-D_i^{\mathrm{R5.1}},\quad
r_i^T=\frac{T_i^{\mathrm{R7.1}}}{T_i^{\mathrm{R5.1}}}.
\]

Report per-stage and combined geometric mean area ratio on jointly passing cases. Record stage-specific Area Sum **only when all 25 cases in that stage PASS**; otherwise label it as a partial sum. Record failure recovery separately. Do not invent area for failed runs, and do not use the incomplete sum to claim a lower area.

### Finally, trade-offs and ablations

Compare `r71_guard` with `r71_policy_off` to isolate the portfolio rule; compare one-kernel ablations to isolate the exact-cover acceleration. Perform additional repeated measurements if close to a time limit, and include a fresh holdout set before claiming generalization.

A legitimate conclusion may be that a guarded policy significantly improves runtime robustness without changing area/delay; a stronger area optimization claim requires direct empirical evidence.

## 5. Output location and automatic packaging

All output folders are unique under `UFUG2106_Round7_1_Delivery/results/<timestamp>/`. The latest path is written to `latest_run.txt`. The exporter reads this pointer and writes a single file under:

```text
UFUG2106_Round7_1_Delivery/feedback/Round7.1_Feedback_<timestamp>.zip
```

The ZIP includes evaluator logs, official CSVs, diagnostics, `summary.json`, generated solver source, headers, source manifest, patchers, and research notes. It **does not** contain the instructor's raw truth-table datasets, evaluator binary, or compiled executables. Check the ZIP file integrity before uploading; the exporter verifies it automatically.

If the experiment terminates before any result folder is created, the exporter still saves error/test logs and a feedback metadata file under an auto-timestamped archive.
